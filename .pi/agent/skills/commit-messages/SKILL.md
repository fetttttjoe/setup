# Commit messages

Three rules. All three, every commit.

## 1. Conventional commits

Format: `<type>(<optional-scope>): <imperative summary>`

Allowed types: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `build`, `ci`, `style`, `revert`.

Subject: ≤72 chars, lowercase after the colon, imperative mood ("add" not "added"/"adds"), no trailing period.

## 2. ≤ 2 lines total

Line 1 is the conventional subject. An optional line 2 is a short body — one sentence of the **why**, not the **what** (the diff shows the what). If the message wants a third line, the change wants to be split into two commits.

## 3. No AI / tool attribution

Never mention Claude, pi, an assistant, a model, "generated by", "co-authored with AI", or any tool that helped author the change. The commit author is the human running `git commit`. `Co-authored-by:` trailers for AI agents are banned.

## Examples

Good:

```
fix(auth): reject tokens with empty subject claim
```

```
refactor(parser): extract token-boundary logic into helper
drops 40 LOC duplicated across the 3 dialect parsers.
```

Bad:

- `Fixed a bug` — not conventional, vague
- `feat: add login (generated with Claude assistance)` — attribution banned
- `feat: large rewrite. Lines 3-30 explain what.` — over 2 lines; split the commit
- `Feat: Add Thing.` — capitalised type, capitalised summary, trailing period

## Self-test

Before running `git commit`:

1. Subject matches `^(feat|fix|refactor|docs|test|chore|perf|build|ci|style|revert)(\([^)]+\))?: [a-z].{0,70}[^.]$`?
2. Total lines ≤ 2?
3. Zero AI/tool/model mentions in the message or trailers?

All three yes → commit. Any no → rewrite.
